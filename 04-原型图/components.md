# 组件与交互规范

## 1. 页面骨架

```
.app
├── aside.side(220px)      品牌块 56px + 分组菜单 + 门店信息
└── .main
    ├── header.top(56px)   面包屑 + 消息铃 + 角色标签 + 头像菜单
    └── .content(24px)     页面标题行 + 筛选区 + 表格/卡片区
```

门户：`header.pnav(64px)` + `.pwrap(1180px 居中)` + 商品栅格。

## 2. 列表页结构（后台 12 个列表页统一）

1. **标题行**：`h1` + 记录数说明 + 右侧主操作（新增/导出）。
2. **筛选区**：白底圆角容器，左侧字典下拉（宽 180）、文本框（宽 200）、日期区间（宽 230），右侧「查询」「重置」，末位显示总数。
3. **表格**：表头不固定宽度、内容自适应；状态列用中文标签；金额与数量右对齐；行内最多「详情 + 1 个高频动作」，其余收进「更多」。
4. **分页**：右对齐，`total, sizes, prev, pager, next, jumper`，默认 10 条。

字段对齐规则：编号/时间左对齐便于扫读，金额/数量/积分数值右对齐。

## 3. 表单与抽屉

- 新增/编辑统一走右侧抽屉（480px），标签在上，单列宽 100%；两字段并排用两列栅格。
- 必填项标签前加红色 `*`，校验失败在字段下方给具体提示，不用统一 toast 代替。
- 业务动作（发券、取消订单、审核退货、人工修正）用居中弹窗，必填「原因（≥5 字）」，危险动作用红色描边按钮 + 二次确认。
- 状态流转类操作严禁直接编辑 `status` 字段，只提供动作按钮。

## 4. 状态标签映射

| 语义 | 标签样式 | 取值 |
|---|---|---|
| 正常/完成 | 绿色 | 正常、在售、已完成、发放中、已发送、低风险、已复购、有效 |
| 进行中/待办 | 藕粉 | 待发货、待发布、未使用、银卡、金卡 |
| 警告 | 橙色 | 待支付、待上架、中风险、待发送、咨询未购、退货中 |
| 危险 | 红色 | 已售罄、已过期、已退款、高风险、已流失、退回、冻结、已驳回 |
| 中性 | 灰 | 已取消、已下架、已停发、未评估、无响应、普通会员 |

## 5. 图表与交互

- 首页 8 个 KPI 卡 + 6 个图表，1440×900 一屏内不出现纵向滚动（卡内边距 12、图高 112、行距 8）。
- 图表点击 → 跳转列表并带入对应筛选条件，统计总数与明细总数必须一致。
- 表格加载 >300ms 显示局部骨架；空状态给出原因与下一步（如「该筛选条件下暂无会员，试试清除风险筛选」）。

## 6. 移动端（<768px）

- 侧边栏折叠为抽屉，筛选项收进底部面板，主按钮固定在安全区。
- 表格转信息卡：只展示编号、状态、时间、负责人，点击进详情。
- 点击区域 ≥44px，底部固定操作区不得遮挡分页。

## 7. 交互文案

- 成功：`已保存`、`已发放 216 张券`、`订单已取消，库存与券已返还`
- 失败：`券已被使用，请刷新后重试`、`数据已被他人修改，请刷新后重试`（版本冲突 4090）
- 二次确认：`取消后库存、优惠券与积分将同时回补，确认取消该订单？`
